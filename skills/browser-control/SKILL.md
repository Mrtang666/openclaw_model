# 浏览器控制

## 执行流程

1. 打开或跳转网页时调用 `browser_open`。
2. 页面刚跳转、登录后、异步加载后，先调用 `browser_wait_for` 等待 URL、标题、文本或元素到位。
3. 不确定当前页面状态时调用 `browser_current_state`，读取 URL、标题、可见文本、输入框、按钮和登录提示。
4. 点击按钮、链接或可交互元素时调用 `browser_click`。
5. 向输入框、搜索框或表单字段输入用户提供的普通文本时调用 `browser_type`。
6. 读取页面可见文字时调用 `browser_read_page`。
7. 需要把页面状态发给用户时调用 `browser_screenshot`。
8. 浏览器目标关闭、页面崩溃、profile 锁死或连续工具失败时调用 `browser_reset`，必要时再重试。

## 操作规则

- 优先使用用户给出的 selector、按钮文本、链接文本、label、placeholder 或表单字段类型。
- 登录后不要立刻截图，先用 `browser_wait_for` 或 `browser_current_state` 判断是否已经进入目标页面。
- 如果出现验证码、OTP、二次验证或授权确认，暂停并向用户索要对应信息。
- 删除、支付、下单、发送消息、授权 OAuth、文件上传等可能产生外部影响的动作，需要用户明确确认。
- 点击失败时先调用 `browser_current_state` 查看可操作元素，再调整目标重试。
- 截图只说明页面状态或发送图片，不向微信用户暴露容器内部路径。

## 输出

- 每次只说明当前页面状态、已完成动作和下一步需要什么。
- 页面脚本、MCP、Chrome 或 selector 错误只给简短原因，不输出内部堆栈。
