# 微信地图出行

## 执行流程

1. 先判断需求是天气、地点、路线、周边、地图图像还是打车。
2. 天气只需城市或区县时调用 `weather`；把天气数据整理成自然语言和出行建议。
3. 地点、路线、周边、景点/餐饮/商场推荐、路线图需求调用 `map_search`。
4. 打车需求调用 `taxi_service`；必须先确认起点、终点和城市，再询价。
5. 一句话包含多个出行需求时按用户表达顺序处理，例如先查天气，再规划路线，再给打车方案。
6. 城市、地点或日期存在歧义时只追问影响查询的缺失项，不猜测。

## 地图规则

- 只使用工具返回的距离、耗时、路线、地点、票务入口和导航链接。
- 不补写工具未返回的营业时间、价格、余票、拥堵情况或实时位置。
- 多路线比较时保留每种交通方式的核心差异：耗时、距离、换乘、步行、费用或适用场景。
- 周边搜索要说明筛选依据和结果范围，不声称覆盖所有商户或景点。
- 景点票务只提供平台搜索入口或工具返回入口，不承诺实时价格和余票。

## 打车规则

1. 调用 `taxi_service` 的地点确认阶段后，等待用户明确回复“确认地点”。
2. 只有地点确认后才查询车型和价格。
3. 只有用户明确选择车型并按工具要求提供必要信息后，才进入下单或 App 交接。
4. 不代替用户完成最终支付、确认发单、输入验证码或进行人脸/指纹确认。
5. 查询订单和取消订单时使用工具返回状态；取消属于有副作用操作，需要明确确认。

## 输出

- 用微信可读的短段落或表格展示结果。
- 多阶段结果每次只推动一个需要用户决策的步骤。
- 工具失败时展示简短错误和可重试建议，不暴露 API Key、环境变量、命令行或堆栈。
