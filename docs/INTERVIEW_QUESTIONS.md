> 适用对象：本仓库的作者或核心开发者。题目以当前代码为准，覆盖 Java/Spring Boot 主应用、CLI、微信多连接 Agent、工具体系、记忆与 RAG、医疗照护协同、浏览器 MCP Sidecar、小红书舆情 Sidecar 与控制台。
>
> 使用方法：先用第 1 部分完成 3 至 5 分钟项目介绍；再按岗位重点抽取第 2 至 13 部分追问；最后用第 14 部分做压力面。回答不要只报类名，统一按“目标与约束 -> 设计选择 -> 关键实现 -> 失败场景 -> 验证方式 -> 已知不足”组织。

## 面试回答自检

每题回答后，先自检以下六件事：

1. 是否明确了当前代码已经做到的部分，而不是把规划当成事实。
2. 是否解释了“为什么这样选”，并说出替代方案和代价。
3. 是否指出了至少一个失败场景和用户可见的处理方式。
4. 是否考虑幂等、权限、隐私、审计、限流或数据一致性中的相关项。
5. 是否能给出对应的代码目录、迁移、接口或测试作为证据。
6. 是否能说出一个真实的已知不足和明确的下一步改进机制，而不是泛泛地说“后续优化”。
